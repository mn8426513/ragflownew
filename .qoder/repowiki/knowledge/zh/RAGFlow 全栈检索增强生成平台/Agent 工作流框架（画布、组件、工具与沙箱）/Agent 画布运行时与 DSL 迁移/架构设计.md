模块由三个职责清晰的文件组成：
- `canvas.py` 定义核心运行时：`Graph` 基类负责解析 DSL、实例化组件（通过 `agent.component.component_class` 工厂）、参数校验与变量引用解析（支持 `{var}` 全局变量与 `{cpn_id@output.key}` 跨组件输出引用）；`Canvas(Graph)` 继承并扩展会话级状态（`history`、`retrieval`、`memory`、`globals`、`variables`），其 `async run()` 是异步生成器，按 `path` 顺序调度组件，使用 `asyncio.Semaphore` + `ThreadPoolExecutor` 并发执行同步/异步组件，并通过 `contextvars` 在协程与线程间传递 LLM 请求上下文、token 用量与 Langfuse 属性。执行过程中产出 `workflow_started/node_started/node_finished/message/message_end/workflow_finished` 等事件流，并内置 TTS 流式切句合成、`userfillup` 交互暂停、错误分支跳转（`categorize`/`switch`/`iterationitem`/`exitloop`）等控制流。
- `dsl_migration.py` 提供纯函数 `normalize_chunker_dsl(dsl)`，将旧版组件名（`Splitter`→`TokenChunker`、`HierarchicalMerger`→`TitleChunker`、`PDFGenerator`→`DocGenerator`）与节点类型（`splitterNode`→`chunkerNode`）映射为当前 schema，同时重写所有字符串值中的组件 ID 引用、`graph.nodes`/`edges` 以及 `history/messages/reference` 字段，保证向后兼容而不改变业务参数。
- `settings.py` 仅暴露模块级常量 `FLOAT_ZERO`、`PARAM_MAXDEPTH`，被上层组件参数校验复用。
依赖方向单向：`canvas` → `dsl_migration` → 外部服务（`api.db.*`、`common.*`、`rag.*`），`settings` 无外部依赖。
