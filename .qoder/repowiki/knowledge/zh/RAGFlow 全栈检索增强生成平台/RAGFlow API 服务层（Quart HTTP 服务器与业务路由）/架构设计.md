模块以 `ragflow_server.py` 为进程入口，启动时初始化日志、加载配置、创建并运行 Quart 应用实例，同时拉起后台线程：一个通过 Redis 分布式锁轮询更新文档处理进度，另一个启动 `api/channels/bootstrap` 中的聊天通道 reconcile 循环。
- 应用工厂位于 `api/apps/__init__.py`：创建 Quart + CORS + QuartSchema 实例，集中实现 JWT / API Token / Beta Token / Session 四合一认证中间件（`_load_user`、`login_required`），并通过 `search_pages_path` + `register_page` 动态扫描 `apps/*_app.py`、`apps/sdk/*.py`、`apps/restful_apis/*.py` 三个目录，按约定前缀 `/v1/<page>`、`/api/v1/`、`/v1/` 自动注册 Blueprint。
- 业务路由分层：`apps/restful_apis/` 下每个文件对应一个领域（chat、document、dataset、models、tenant 等），调用 `apps/services/*_service.py` 进行参数校验与编排；`apps/auth/` 提供 GitHub/OAuth/OIDC 登录；`apps/backward_compat.py` 提供旧版 API 兼容路由。
- 数据访问层在 `api/db/`：`db_models.py` 定义 Peewee ORM 模型，`services/` 中每个 Service 类封装对单表的 CRUD 与复杂查询，`joint_services/` 封装跨表聚合逻辑；`init_data.py` 负责建表与初始数据填充。
- 多渠道接入在 `api/channels/`：`core/base.py` 与 `core/registry.py` 定义 Channel 抽象与构建器注册表，各平台（feishu、discord、telegram、wecom、dingtalk、line、qqbot、whatsapp）以独立子包实现；`bootstrap.py` 每 10 秒对比 DB 中 `chat_channel` 表与运行实例，按需启停/重启。
- 公共能力集中在 `api/common/`（异常、RBAC、base64）、`api/utils/`（分页、加密、图片、文件响应、模型工具等）以及根级 `constants.py`、`validation.py`。
依赖方向严格自上而下：HTTP 路由 → services → db.services → db_models，channels 子系统通过 `ChatChannelService` 与主服务解耦。
