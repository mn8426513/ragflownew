模块由 `cmd/` 下的两个 main 包构成：`ragflow_server.go` 是主服务入口，通过命令行参数 `--api|--admin|--ingestor|--syncer` 选择运行模式；`ragflow-cli.go` 是独立的 CLI 工具。所有进程共享 `internal/server` 配置子系统（基于 viper，从 YAML 与环境变量 `RAGFLOW_*` 加载），并依次初始化日志、数据库 (`dao.InitDB`)、文档引擎 (`engine.InitDocEngine`，支持 elasticsearch/infinity/oceanbase/seekdb/serenedb)、Redis 缓存、消息队列 (NATS) 与存储工厂 (`storage`)，再按模式调用 `runAPI/runAdmin/runIngestor/runSyncer`。

- HTTP 层：`internal/router` 集中注册 `/api/v1/*` 路由，按无认证组、Beta Token 组、鉴权中间件分组挂载到 Gin Engine；`internal/handler` 实现具体请求处理，依赖 `internal/service` 业务层，service 再调用 `internal/dao` 数据访问与 `internal/engine` 文档引擎。
- 进程职责分离：API 进程启动 Gin + channels（钉钉/飞书/企微/Telegram/WhatsApp/Discord/Line 等多渠道接入）+ MCP Server；Admin 进程仅暴露管理端点；Ingestor 进程消费 NATS 任务执行文档解析与知识编译；Syncer 进程负责外部文件系统同步。
- 扩展点：`*_ee.go` 后缀文件承载企业版功能（如 admin/license_ee、router_ee、handler/system_ee），通过 Go build tag 或条件编译与开源版本共存；`internal/engine` 子目录为各后端存储/消息队列/分析引擎的插件式实现，通过 `DocEngine`/`MessageQueue` 接口抽象。
- Agent 运行时位于 `internal/agent`，包含 DSL 解析、Canvas 图执行、组件库 (`component/`)、沙箱 (`sandbox/`)、TTS (`audio/`)、Harness 测试框架等，由 service 层在启动时通过全局 setter（如 `component.SetMemorySaver`、`nav.SetNavService`）注入。
