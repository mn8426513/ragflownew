SDK 以 `ragflow_sdk/` 为包根，`ragflow.py` 中的 `RAGFlow` 类作为唯一入口，负责维护 `api_key`、`base_url`、`Authorization: Bearer` 请求头，并暴露 `get/post/put/delete/patch` 等底层 HTTP 方法以及按资源域（dataset/chat/chunk/document/agent/memory）组织的业务方法；每个业务方法将后端返回的 JSON 数据包装成对应模块类实例。

- `modules/base.py` 定义 `Base` 基类：通过 `_update_from_dict` 递归将响应字典转为属性，并提供 `to_json()` 序列化及透传 `post/get/rm/put/patch` 到宿主 `RAGFlow` 实例，所有资源对象均继承自它。
- `modules/` 下每个文件对应一个资源域（`dataset.py`、`document.py`、`chunk.py`、`chat.py`、`session.py`、`agent.py`、`memory.py`），实现该资源的 CRUD 与领域操作（如 `DataSet.parse_documents` 内置轮询解析状态）。
- `__init__.py` 在包导入时调用 `beartype.claw.beartype_this_package()` 启用运行时类型检查，并通过 `__all__` 显式导出 `RAGFlow`、`DataSet`、`Chat`、`Session`、`Document`、`Chunk`、`Agent`、`Memory`。
- 依赖方向单向：`RAGFlow` → `modules/*` → `modules/base.Base`，模块之间仅通过 `Base` 和 `RAGFlow` 耦合，无循环引用。
- 测试位于 `test/`，使用 pytest + `conftest.py` 自动注册/登录用户、配置 ZHIPU-AI 模型实例与默认 LLM/embedding/vision 模型，通过 `HOST_ADDRESS`、`ZHIPU_AI_API_KEY` 环境变量驱动。
