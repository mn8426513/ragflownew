测试套件按运行目标分层组织：
- `unit_test/`：针对 ragflow 源码各模块的单元测试，目录结构与被测包镜像（agent、api、common、data_source、deepdoc、rag、memory、mcp 等），通过 `unit_test/conftest.py` 在导入前配置 NLTK 数据路径并自动下载缺失资源。
- `testcases/`：面向已部署服务的集成测试，按客户端类型划分为 `restful_api`（requests）、`test_http_api`、`test_sdk_api`、`test_web_api`、`test_admin_api`；共享配置集中在 `configs.py`（解析 docker/.env、HOST_ADDRESS、ZHIPU_AI_API_KEY 等），并通过 `conftest.py` 中的 `pytest_addoption('--level')` 将 p1/p2/p3 映射到 marker 表达式，session 级 fixture `auth`/`token`/`set_tenant_info` 自动注册/登录并为租户绑定 ZHIPU-AI 与 SILICONFLOW 模型实例。
- `playwright/`：基于 Playwright + pytest 的浏览器 E2E，`helpers/` 封装 `_auth_helpers`、`_next_apps_helpers`、`flow_steps`、`response_capture` 等复用逻辑，`auth/` 与 `e2e/` 分别覆盖认证流程与 Next Apps 场景。
- `benchmark/`：可独立通过 `uv run -m benchmark <chat|retrieval>` 运行的 HTTP 基准 CLI，由 `__main__.py` 入口、`cli.py`、`http_client.py`、`metrics.py`、`report.py` 组成，配套 `run_chat.sh`/`run_retrieval.sh`/`run_retrieval_chat.sh` 脚本一键编排数据集创建、文档上传解析与压测。
- `integration/wiki/`：针对 Wiki 增量能力的独立集成用例。
- `fixtures/`：存放 JSON 测试数据（mineru 页面内容、term_weight_oov）。依赖方向单向：上层测试 → 共享 conftest/fixtures → 被测服务 HTTP/SDK，不反向引用业务代码。
