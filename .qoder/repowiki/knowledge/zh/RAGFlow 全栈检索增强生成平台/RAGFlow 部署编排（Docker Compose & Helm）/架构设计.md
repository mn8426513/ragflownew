本模块由两套并列的部署方案组成：
- `docker/`：基于 Docker Compose 的多 profile 编排。`docker-compose.yml` 通过 `include` 引入 `docker-compose-base.yml` 拉起 MySQL、MinIO、Redis、Elasticsearch/OpenSearch/Infinity、Nginx 等依赖，再按 `cpu`/`gpu` profile 启动 ragflow-cpu/ragflow-gpu 两个服务；环境变量统一来自 `.env`，运行时通过挂载 `service_conf.yaml.template` 与 `entrypoint.sh` 实现配置热替换，Nginx 子目录提供 `nginx.conf`、`proxy.conf` 以及 Python/Go/Hybrid 三种 `ragflow.conf.*` 反向代理模板。
- `helm/`：标准 Helm Chart（`Chart.yaml` v2），`values.yaml` 集中声明所有组件镜像、资源、存储与开关；`templates/` 下每个依赖（mysql、minio、redis、elasticsearch/opensearch/infinity、ingress）独立为一份 YAML 模板，并通过 `_helpers.tpl` 共享命名与标签；RAGFlow 主应用由 `ragflow.yaml` 渲染 Deployment/Service，`env.yaml` 将 values 转为 Secret/ConfigMap，`ragflow_config.yaml` 生成 service_conf 覆盖文件，Nginx 配置以 ConfigMap 形式挂载进容器。
依赖方向：Helm 与 Compose 均只负责编排与配置注入，不耦合业务代码；两者通过同一份 `.env`/`values.yaml` 语义对齐（如 `DOC_ENGINE`、`MYSQL_*`、`MINIO_*`、`REDIS_PASSWORD` 等）。
